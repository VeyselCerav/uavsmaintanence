# 09 — i18n Mimarisi

Diller: `tr` (varsayılan), `en`, `az`.  
Azerbaycan Türkçesi alfabesi tam destek: ə Ə ı İ ö Ö ü Ü ç Ç ş Ş ğ Ğ.

## 1. Kaynaklar

```text
frontend/i18n/tr.json
frontend/i18n/en.json
frontend/i18n/az.json
```

Kullanıcıya görünen her metin buradadır. JSX içinde `"Bakım Ekle"` yasaktır.

```ts
t("maintenance.add")
// TR: Bakım Ekle
// EN: Add Maintenance
// AZ: Texniki xidmət əlavə et
```

## 3. Locale seçimi

Öncelik:

1. Kullanıcı profili `locale`  
2. `Accept-Language`  
3. `tr`

Tarih:

| Locale | Örnek |
|---|---|
| tr | 17.08.2026 |
| en | 08/17/2026 |
| az | 17.08.2026 |

Sayı ve para: `Intl`. Desteklenen para: TRY, USD, EUR, AZN.

## 4. Backend

- API `error.code` + `message_key` döner.  
- Katalog varlıklarında `code` değişmez; `name` tek dilde saklanır **veya** `name_i18n` jsonb (`{"tr":"...","en":"...","az":"..."}`).

**Önerilen karar (ADR-11):** Katalog `name` alanı varsayılan dilde (TR) tutulur. Çeviri ihtiyacı olan sistem etiketleri i18n JSON’dadır. Kullanıcı tanımlı sınıf adı üç dilde zorunlu değildir; isteğe bağlı `translations` jsonb eklenebilir. PDF aktif locale ile üretilir; TR ad yoksa `code` basılır.

## 5. PDF / Excel

Rapor şablonları locale’e göre etiket çeker. Dosya adı: `bakim-raporu-2026-08-17.pdf` locale’e göre değişmez (teknik); başlık değişir.

## 6. Kalite kuralı

- Yeni ekran = aynı PR’da üç JSON güncellenir.  
- CI: üç dosyada anahtar kümesi eşit değilse build kırılır.  
- AZ metinleri Türkiye Türkçesi kopyası olamaz; teknik terimler AZ karşılığı ile yazılır.
